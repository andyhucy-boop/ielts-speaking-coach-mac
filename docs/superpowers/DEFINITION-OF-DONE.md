# 成品标准：做到什么程度算做完

日期：2026-08-05

这份文件回答一个问题：**这个东西做完之后，用户能做到什么？**

路线图讲「要建什么」，实施计划讲「怎么建」，这份讲「建成了是什么样」。三者不一致时，**以这份为准**——功能做完了但用户做不到下面这些，就不算做完。

---

## 0. 一句话

**打开 App，三次点击之内开始说英语；说完，复盘和录音自动归档；下次打开，知道该练什么、上次哪里没说好、那个毛病有没有改掉。**

---

## 1. 用户是谁

一位准备雅思的考生。目前口语 6 分，有一对一辅导，会用 ChatGPT Voice 练口语。

他的真实痛点不是「不会说」，而是**练习前后的杂事**：

- 每次要自己想今天练什么
- 每次要重新输一遍提示词
- 练完的复盘散在聊天记录里，翻不回来
- 想回听自己怎么说的，得另外用手机录
- 上次被指出的毛病，这次有没有改掉，不知道

**这个工具解决的是这些杂事，不是替他说英语。**

---

## 2. 一次完整使用应该是什么样

### 开练（目标：≤ 3 次点击，≤ 30 秒）

1. 双击图标打开 App
2. 首页已经显示「今天练什么」——不用想
3. 点一下「开始」

然后：ChatGPT 自动打开、自动进语音、自动收到考官提示词。**用户什么都不用输、不用复制、不用切窗口。**

30 秒里有约 10 秒是 ChatGPT 语音本身的启动耗时（实测 9 秒，spec 2.3.7），这部分压不下去，但**必须有明确的进度提示**，不能让人对着不动的界面猜。

### 练（目标：像真考试）

- 考官一次问一个问题，不中途打断、不提前给反馈（除非用户选了「当场点出」）
- Part 2 给一分钟准备（或按用户设置由他自己决定）
- 用户说「stop the test」或在界面上点结束，都能停

### 练完（目标：零手工整理）

练习结束后自动完成：

- 复盘取回并存档
- 错题进错题本，重复出现的累加次数
- 推荐词汇进词汇本
- 下次的重点目标被记下
- 计划进度前进一格
- 录音存好（若用户开了这个开关）

**用户唯一要做的是关掉窗口。**

若自动取复盘失败，必须**明确告诉用户失败在哪、下一步怎么办**，且**已经产生的内容一点都不能丢**——练了半小时换来的复盘，不能因为解析出错就没了。

### 回看（目标：想找的都能找到）

打开 App 就能看到：

- 本周练了几次、离目标还差几次
- 最近几次练了什么题
- 哪些毛病在反复出现、出现了几次、最近有没有变少

点进任何一次练习，能看到：

- 当时的题目
- **完整的问答逐字稿**——考官问了什么、自己怎么答的
- 那次的完整复盘
- **能听自己当时怎么说的**（若开了录音）

### 改进闭环（这是产品真正的价值所在）

1. 复盘给出**一个**具体目标（不是「提高词汇量」这种空话，是「回答后补一个原因和例子」这种能做到的行为）
2. 点一下「带着这个目标重练」，同一道题再来一次
3. 再换一道题验证——**是真会了，还是只记住了那个答案**
4. 在问题档案里看到这个毛病的出现次数有没有下降

## 3. 可验收的硬标准

做完之后，下面每一条都必须能当场演示：

| # | 标准 | 怎么验 |
|---|---|---|
| 1 | 从双击图标到开口说第一句，**≤ 3 次点击** | 数点击次数 |
| 2 | 全程不需要打开终端 | 把终端关掉再走一遍全流程 |
| 3 | 不需要手动输入或复制任何提示词 | 观察 |
| 4 | 练完后错题本、词汇本、重训目标**自动有内容** | 练一场，看三处数字是否从 0 变正 |
| 5 | 逐字稿里能找到考官问过的每一个问题 | 对照 ChatGPT 窗口逐条核 |
| 6 | 能听到自己那次的录音（若已开启） | 点播放 |
| 7 | 任何一步失败，**已产生的内容都还在** | 人为制造失败（如断网、关掉 ChatGPT），检查 `pending-reviews/` |
| 8 | 任何一条错误信息都说清「发生了什么 + 下一步做什么」 | 逐条读，找一个不懂技术的人试着照做 |
| 9 | 重新编译打包后，**不需要重新授权** | 连打包两次，第二次直接开 |

## 4. 明确不做的事

写下来是为了防止范围无限扩大：

| 不做 | 为什么 |
|---|---|
| **不预测雅思分数** | 复盘里给「你大概 6.5 分」这种数字，既不准也有害——会让人盯着数字而不是盯着问题。上游的复盘规范也明确禁止按词数推断分数 |
| **不替代真人老师** | 它整理练习前后的杂事，不评判你的水平。你的一对一辅导解决的是它解决不了的问题 |
| **不录 ChatGPT 的声音** | 只录你自己。考官问了什么由逐字稿给文字。录对方声音要屏幕录制权限，代价不值（见 ROADMAP 3.3）|
| **不做手机端** | macOS 桌面工具。练口语本来就该在安静的桌前 |
| **不做云同步、不做多用户** | 数据只在本机。想换机器就拷目录 |
| **不内置商业题库** | 只带原创样例。你自己的题库自己导入 |
| **不调用 OpenAI API** | 复盘由你自己的 ChatGPT 账号生成，不产生额外费用 |

## 5. 怎么判断「成了」

上面十二条硬标准是**必要条件**，但不是充分条件。

真正的判据只有一个：

> **你会连着用它练一周吗？**

如果做完之后你还是宁愿直接打开 ChatGPT 自己敲提示词，那说明这个工具没做成——不管功能表打了多少勾。

所以每个阶段做完都要你真用一次并如实反馈，包括「哪里让我不想用」。**这类信息我拿不到，只有你有。**

Phase 2 已经证明过一次：六个真机缺陷里有两个（Live 只能在全新会话启动、正确顺序是先 Live 后发消息）纯粹来自你的使用经验，AX 树上一点痕迹都没有。

## 7. 两个已知的规划缺口（已补，2026-08-05）

写这份文件时发现的，都已补进 Phase 3 的实施计划：

1. **Phase 3 做完仍不能在界面里开练。** 原计划把「界面」和「驱动接进界面」分了两步，Phase 3 的「开始练习」按钮只会提示用户去终端——违反硬标准第 2 条。
   → **已补为 Phase 3 Task 9**，驱动接入从 Phase 4 提前到 Phase 3。
2. **题库 PDF 无人处理。** 导入只支持 CSV/JSON，而用户手上的季度题库是 PDF。不解决它，Phase 3 做完连题都没得练。
   → **已补为 Phase 3 Task 8**。

另外补了 **Task 7：设计令牌与基础组件**，依据 `DESIGN-SYSTEM.md`。这一条不是缺口，是把「界面要美丽」从主观评价变成可验证的东西：五个能自动跑的对比度测试 + 十条人工验收清单。
