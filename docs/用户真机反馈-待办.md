### 补充：`strings | grep` 这个验法有个坑，会骗人

release 构建（`-O`）下，**UTF-8 长度 ≤15 字节的字符串字面量会被编成立即数**
（Swift small-string optimization），根本不以连续字节存在二进制里。
所以 `grep -a "Part 3 theme"`（14 字节那一段）在包里数出来是 **0 次**，
但那句话照样会打印出来。

本次的对照实验：用同一份源码、同样 `-O` 编出 `./.build/release/coach`，
它跑出来的第一行就是 `Part 3 theme: a shop or store you enjoy visiting`，
而在它自己的二进制里 `grep -a "Part 3 theme"` 同样是 0 次。

**结论：只用超过 15 字节的句子当探针。** 例如
`That line is the background theme this set of discussion questions belongs to`（在包里 1 次）。

## 一、随机抽题 —— 已做

今日训练页多一条「随机抽题练一场」。三个步进器定每个 Part 抽几道，抽完把抽到的整组
逐条列出来，再点「开始练习」。

它顺带补掉了一个一直存在的洞：**组合档从前只供一段的料**，其余几段由考官现编
（`ExaminerPrompt` 里那句 "Choose your own material for …"）。随机抽题一次供全，
所以「抽到 3 个话题就问这 3 个」这件事在提示词里是硬约束，不是建议。

**Part 3 跟着抽到的 cue card 走**（`LinkedPart3`）。独立随机抽会出现「卡讲逛商店、
讨论题问环保立法」，而提示词白纸黑字要求 Part 3 顺着 Part 2 的主题——两者当场打架。

## 二、只抽没练过的 —— 已做

判据是 `Question.status == "practiced"`，与训练题库页那个 ✓ 是同一个标记。

顺带修了一处会静默记错账的地方：一场抽 5 道全练了，从前只记开场那一道，
于是另外 4 道永远停在「新题」，「只抽没练过的」会一遍遍再抽出来
（`PracticeSession.drawnQuestionIds`）。

## 本次没做的（留着，写清原因）

   **下一步**：真想要一个会转的圆盘的话，得先把候选池收窄到十来个才有意义

2. **跟着 cue card 抽出来的那几道 Part 3 不看「练没练过」。**
   它是那张卡自己的讨论题，换一道就等于讨论和卡讲的不是一件事。
   卡本身已经按开关筛过了，所以正常情况下它的追问也是新的。
   **这是有意的，不是漏判**，代码里写着理由（`RandomDraw.draw`）。

3. **命令行与 MCP 都还抽不了题。** `coach practice` 只吃一个题号，
   MCP 那几个工具同理。App 里能用就够这次的要求了。
   **下一步**：真要的话，给 `coach practice` 加 `--random 2,1,1` 一类的参数，
   走的是同一个 `RandomDraw`，不必再写一份取数逻辑。

4. **抽到的题在「点我练完了」那一刻整组算练过**，与开场那道题的口径一致。
   改成「答完才算」需要逐题回执，而语音会话里拿不到那种回执。

   > **更正（同日晚，对照上游时查出来的）**：这一条原先写的是
   > 「开练那一刻就算练过，中途放弃也算」，**两句都是反的**。
   > `upsertSession` 全工程只有两个调用点，都在收尾链路上
   > （`finishPractice` 与 `archive`）；`cancel()` 一个字都不写盘——
   > 放弃那一场既不进训练记录，也不会把任何题标成已练。
   > 真正的缺口是反过来那一件：**练到一半崩了 / 误退 / 重启，整场就没了**
   > （上游一开练就落盘，逐字稿每 450 毫秒存一次）。

5. **验包探针不要用 `strings`。** 这次实测：`strings -a` 对这个二进制里的中文
   一次都匹配不到（它只吐可打印 ASCII，多字节 UTF-8 被切碎），
   连 1.0.0 的旧文案都是 0 次。**要用 `LC_ALL=C grep -a -o` 直接搜二进制**，
   探针仍然只用超过 15 字节的句子。
