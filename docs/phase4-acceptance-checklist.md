### ⚠️ 计划 Task 13 Step 7 的制造失败方式，不会产生待处理的复盘

计划原文让你「在 ChatGPT 输出复盘的过程中把 ChatGPT 窗口关掉（或断网）」，然后去
「重新导入待处理的复盘」里找这一条。**照做的话那个列表会是空的**，而这不是缺陷。

原因：`pending-reviews/<编号>.txt` 是在 `PracticeRunner.archive()` 里写的
（`Sources/IELTSCoachUI/Session/PracticeRunner.swift:339`），而 `archive()`
**只有在复盘原文已经成功取回之后**才会被调用。窗口关掉 = 取不回来 = 走不到落盘那一步。

真正能走到落盘、又能让入库失败的路径是「**取回来了，但格式不对、解析不出来**」。
第 8 节给了两个都要做的版本：**8A 才是决策 2 的验收**，8B 验的是「失败时已产生的内容还在不在」。

## 3. 【最先做】用 `axprobe dump` 回答本阶段最大的未知（约 10 分钟）

**这一步不用练整场，也不依赖第 1 节那个阻断项。** 它直接看 ChatGPT 的 AX 树，
回答两个问题：语音会话里的字幕**读不读得到**、说话人**判不判得出**。

> 这一步要用终端。**这不违反「全程不需要打开终端」那条硬标准**——那条标准约束的是
> 产品的日常使用，而这里是诊断。第 4 节开始就把终端关掉。

**前提**：跑 `axprobe` 的那个终端 App 自己需要「辅助功能」权限
（系统设置 › 隐私与安全性 › 辅助功能里勾上 Terminal / iTerm）。
**这与你给 `.app` 的授权是两份，各授各的**，勾了终端不会让 `.app` 生效，反之亦然。

### 3.1 采集

1. 手动打开 ChatGPT，**新建一个会话**，点开语音（不用本工具，就手动开）
2. 真的说两三句英文，让它答两三句，**保持语音会话开着不要挂断**
3. 切到终端，跑：
   ```bash
   cd ~/Projects/ielts-speaking-coach-mac
   swift run axprobe dump /tmp/ax-voice.txt
   ```
4. 然后**挂断语音**，等 ChatGPT 把整段对话以普通消息形式留在会话里，再跑一次：
   ```bash
   swift run axprobe dump /tmp/ax-after-voice.txt
   ```

两份都留着，附进验收报告（或至少把下面几条 grep 的输出抄进去）。
**两份必须都采**：本工具是在练习**进行中**每 2.5 秒采一次样，不是挂断后采一次，
所以 `ax-voice.txt` 那份才是决定性的；`ax-after-voice.txt` 是对照组。

### 3.2 判读（对着 `/tmp/ax-voice.txt` 跑）

**问题一：你说的话，在 AX 树里读得到吗？**

```bash
grep -n "你刚才说过的某个英文词" /tmp/ax-voice.txt
grep -c "AXStaticText" /tmp/ax-voice.txt
```

| 结果 | 含义 | 记进报告 |
|---|---|---|
| 搜得到你说过的原话 | 字幕在 AX 树里，逐字稿这条路走得通 | 抄一行原文 |
| 搜不到，但 `AXStaticText` 有几十上百个 | 字幕可能被拆成碎片或换了角色，需要人眼在 dump 里翻一下 | 把附近的节点抄下来 |
| **完全搜不到** | **语音会话的字幕根本不在 AX 树里**（比如画在 canvas 上）。这比说话人判不出严重得多——逐字稿会是空的，Phase 4 的核心交付不成立 | **立刻停下来报告**，别再练那 6–8 分钟 |

**问题二：说话人判得出吗？（本阶段最大的未知）**

```bash
grep -n 'desc="Copy"' /tmp/ax-voice.txt          # ChatGPT 回复的复制按钮
grep -n 'desc="Copy message"' /tmp/ax-voice.txt  # 你自己那条消息的复制按钮
# 有的节点的标签落在 title 而不是 desc 上，两个都要看一眼：
grep -n 'title="Copy' /tmp/ax-voice.txt
# 中文界面下这两个标签分别是「复制」和「复制消息」：
grep -n '复制' /tmp/ax-voice.txt
```

（判据用的是 `label`，也就是「desc 非空就取 desc，否则取 title」，见 `AXElementRef.swift:42`。
所以 `desc=` 和 `title=` 两种写法都算命中。）

判据（三重，缺一不可，见 `ChatGPTLabels.speakerMarker`，`Sources/ChatGPTBridge/ChatGPTLabels.swift:126`）：
命中行的角色必须是 `AXButton` 或 `AXCheckBox`，**且** `children=1`，**且**紧接的下一行是缩进一级的 `AXImage`。

| 看到什么 | 结论 | 后果 |
|---|---|---|
| 两个 grep 都有命中，且都满足上面三重判据 | ✅ 说话人判别在语音会话里**成立** | 逐字稿会正确区分「考官」和「我」 |
| 只有 `Copy`，没有 `Copy message` | ⚠️ 只判得出考官 | 你自己说的话会全部标成「说不准是谁说的」 |
| **两个都没有命中** | ❌ 说话人判别在语音会话里**不成立**（这正是那个未知的坏结果） | 逐字稿的**内容与顺序仍然完整**（成品标准第 5 条仍可能达标），但每一条都标「说不准是谁说的」，并弹出「本次逐字稿可能不完整：有 N 段没能判断是考官说的还是你说的…」 |
| 命中了标签，但 `children` 不是 1、或下一行不是 `AXImage` | ❌ 结构判据不满足，`speakerMarker` 返回 nil，效果同上一行 | **把那几行原文一字不差抄进报告**——它直接决定 `speakerMarker` 该怎么改 |

**再对照一下 `/tmp/ax-after-voice.txt`：** 挂断之后那两个按钮是不是就出现了。
若是「语音中没有、挂断后才有」，那是个重要发现：说明**练习结束后补采一次**能救回说话人，
值得作为下一轮的改法记进报告（现在的实现在 `finishPractice()` 第一件事就 `collector.finish()`，
那一次采样正好发生在挂断之前）。

**这一步无论结果如何都不算失败。** ROADMAP 第 6 节早就把逐字稿拼接列为已知风险，
写着「需真机多轮验证」。**把现象记清楚，才是这一步的价值。**

## 5. 逐条核对逐字稿（计划 Step 3，成品标准第 5 条）

到「训练记录」页，点开刚才那一场（点行卡片本身，不是右边的垃圾桶图标）。
**对照 ChatGPT 窗口逐条核**，七项逐项写进报告：

| # | 要核的 | 怎么判断 |
|---|---|---|
| 1 | **考官问过的每一个问题都能找到** | 把 ChatGPT 窗口里考官的每一句提问，在逐字稿里挨个找。**一句都不能少**——这是成品标准第 5 条 |
| 2 | 自己说的话在不在 | 语音转文字本身不准不是本工具的问题。核的是「有没有这一条」，不是「字对不对」 |
| 3 | **说话人判对了没有** | 考官的话标「考官」（靠左）、自己的话标「我」（靠右）。标成「说不准是谁说的」（橙色）的**记下实际比例，如 12 条里 12 条** |
| 4 | 有没有重复 | 同一句话出现两遍及以上 = 拼接规则有问题。**把重复的原文抄进报告** |
| 5 | 有没有混进不是对话的东西 | 侧边栏会话名、按钮说明、考官提示词的片段。**把混进来的原文一字不差抄进报告** |
| 6 | 顺序对不对 | 是不是按实际发生顺序排的 |
| 7 | 完整性提示 | 若显示了「本次逐字稿可能不完整…」，**把整句抄下来**。它应该同时说清「几次失败/几段判不出」「练习本身和复盘都不受影响」「下一步做什么」 |

### 按现象定位该改哪儿（计划给的表，加了三行子代理复核时想到的）

| 现象 | 改哪儿 |
|---|---|
| 说话人大面积判不出 / 判反 | `ChatGPTLabels.speakerMarker`（`Sources/ChatGPTBridge/ChatGPTLabels.swift:126`）——**只改这一个函数** |
| 同一句话重复出现 | `TranscriptAssembler` 的合并规则（`Sources/IELTSCoachCore/Transcript/TranscriptAssembler.swift`） |
| 混进侧边栏、按钮文字 | `AXTranscriptSampler` 的过滤（`Sources/ChatGPTBridge/AXTranscriptSampler.swift`），或把它们纳入背景板 |
| 缺了考官的某个问题 | 先看是不是被当成背景板滤掉了（`TranscriptAssembler.seedBaseline`） |
| **同一句话的好几个「半截版本」各占一行** | 语音字幕可能是**边听边改写**（不是只往后长）。现在的合并规则要求两个版本互为前缀（`canMerge`），改写就匹配不上，会各开一个槽位。**把这几行原文抄下来**，它决定要不要引入相似度合并 |
| **整份逐字稿只有寥寥几条，但你说了很多** | 采样节拍（2.5 秒）跟不上，或字幕节点会被整体替换。记下「实际说了几轮 / 记下来几条」 |
| **一条里混了考官和自己两个人的话** | 采样器把复制按钮之前攒的所有文本都归给同一个说话人（`AXTranscriptSampler.sample()`）。若语音字幕里两个人的话之间没有按钮分隔，就会粘成一坨。**抄一条粘连的原文** |

> **改完之后必须给那个现象补一条测试，再练一场复验。** 没有测试的修复，下一次改动就会把它弄回去。

**必须直接跑包里那个可执行文件，不能用 `open`**：`open` 走的是 LaunchServices，
它不会把你在终端里设的环境变量传给 App，你会看到的还是真实数据目录——
而那正好长得像「环境变量没生效」和「空状态坏了」都说得通，最容易看走眼。
这一次会走一遍权限检查页，需要的话点「先跳过」即可（只看空状态用不到辅助功能）。

## 7. 开关会不会掉 + 单条删除（计划 Step 5、Step 6）

### 7A 开关持久化

1. [ ] 把「记录对话逐字稿」**关掉**
2. [ ] **完全退出 App**（⌘Q，不是关窗口），再打开
3. [ ] 开关必须**还是关着的** —— 掉了的话多半是 `AppState.setTranscriptEnabled` 没写进盘，
       或 `CoachSettings` 的 `CodingKeys` 漏了字段
4. [ ] 再练一场（可以很短），确认这一场的逐字稿是空的、且**没有**弹出「逐字稿不完整」的警告
       —— ⚠️ **第 1 节那个阻断项没修之前，这一条是假通过**（开着也一样是空的），修完要重验
5. [ ] 把开关打开，恢复默认

### 7B 单条删除（决策 4）

1. [ ] 挑一条**有复盘**的记录（右边写着「复盘已存档」），先到数据目录 `reports/` 里
       记下它对应的文件名（`<会话编号>.json`）
2. [ ] 点行尾的垃圾桶图标，**读确认对话框**。它应该：
       - 标题说清是哪一场：「删掉 8 月 6 日 那一场（Part 1·某某题目）？」
       - 正文逐条列明会删什么、并说清什么**不会**删：
         「删掉之后，这一场的训练记录和逐字稿、它的复盘报告都会从磁盘上消失，无法恢复。
         已经归进错题本和词汇本的内容不会跟着删——那些是跨场累积的，只删这一场不会让它们对不上。
         下一步：想留着就点「取消」；确认之后立刻生效，不进废纸篓，也没有撤销。」
       - **看得懂吗？敢按吗？** 这个感受请记下来
3. [ ] 点「删除这一场」
4. [ ] 到数据目录看 `reports/<编号>.json` 是不是**真的没了**
5. [ ] 到「复盘报告」页确认这一场不再列出
6. [ ] 打开 `state.json`，确认 `issues` / `vocabulary` **没有**跟着变少（跨场累积的东西不该被单场删除牵连）

## 8. 「重新导入待处理的复盘」（计划 Step 7，决策 2）

**注意：计划原文那个做法产不出待处理的复盘，原因见第 1 节。** 下面 8A 才是决策 2 的验收。

### 8A 让复盘「取得回来但入不了库」——这条才会落盘

1. [ ] 再练一场，很短即可（两三个问题）
2. [ ] 点「我练完了」
3. [ ] **在 ChatGPT 开始写复盘、写到一半时，按 ChatGPT 自己那颗「停止生成」按钮**，
       让输出被截断（超过 60 个字符就够本工具去取它了，但 JSON 是残缺的）
4. [ ] App 应当停在失败态，显示一段中文，要点：
       - 「复盘取回来了，但不是本工具认得的格式，解析不出来（…）」
       - 「**原文一个字都没丢**，就在 …/pending-reviews/<编号>.txt，这一场也已经记进训练记录了」
       - 「下一步：先点「重新取复盘」再取一次；…再到「复盘报告」页用「重新导入待处理的复盘」把这份原文补进来」
5. [ ] **确认这段文案里没有出现「终端」「命令行」「coach reimport」**——出现了就是决策 2 没落实
       （子代理已静态查过一遍：`Sources/IELTSCoachUI/` 与 `Sources/IELTSCoachCore/` 里，
       这三个词在**复盘取回、解析、归档、重新导入**这几条路径上一处都没有进入用户可见文案，只出现在代码注释里。
       唯一一处进了界面的是 `PermissionStatus.diagnosticsText` 里那句「宿主：命令行」——
       那是环境诊断在陈述自己跑在哪儿，不是把用户推回终端，与决策 2 无关。
       这一条现在预期能通过，但仍请你在屏幕上亲眼确认一次）
6. [ ] 到「复盘报告」页，看右上角那颗「重新导入待处理的复盘」，它下面应该写着「待处理 N 份」
7. [ ] 点开它，核对这一条的：**时间**（何时落的盘）、**会话编号**、**字节数**、**题目**——对不对
8. [ ] 点「查看原文」，确认能看到 ChatGPT 当时到底输出了什么（应当能选中复制）
9. [ ] 这份原文是残缺的，所以点「重新导入」应当**失败并说清原因**——把那句话抄下来
10. [ ] 回 App，点失败面板上那颗「**重新取复盘**」（这是解析失败时会出现的那一颗，
        不是「我已经复制好了」——后者只在两条自动路都断掉、界面转到「需要手动复制」时才出现）。
        它会让 ChatGPT 重新写一份完整的复盘再取一次，应当能成功归档。
        若它把界面转到了「需要手动复制」，就照屏幕上说的：切到 ChatGPT 选中整段复盘
        （含首尾那两行 `<<<…>>>` 标记）按 ⌘C，回来点「我已经复制好了」
11. [ ] 确认错题本 / 词汇本的数字比第 4 节抄下来的**变大了**
12. [ ] 回收件箱点「刷新」，确认那一条**已经从列表里消失**（`.imported` 标记生效）

### 8B 中途把 ChatGPT 关掉（验的是「已产生的内容都还在」）

1. [ ] 再练一场，很短即可
2. [ ] 点「我练完了」之后，**在 ChatGPT 输出复盘的过程中把 ChatGPT 窗口关掉**
3. [ ] App 应当停在失败态，文案说清发生了什么 + 下一步；**同样不许出现「终端」「命令行」**
4. [ ] **这时「重新导入待处理的复盘」列表里不会有这一条，这是对的**（原文压根没取回来，见第 1 节）
5. [ ] 但「训练记录」里**必须**有这一场（题目、时间、逐字稿都在，只是「没有复盘」）——
       这才是成品标准第 7 条要验的：**任何一步失败，已产生的内容都还在**
6. [ ] 如果这一场在训练记录里**找不到**，那是严重缺陷，立刻停下来报告

## 11. 出事了怎么退回去

- **训练数据被改坏 / 误删** → 用第 2 节备份的那份文件夹整个换回去（App 要先 ⌘Q 退出）
- **复盘原文还在** → `pending-reviews/` 里的 `.txt` 一律不会被自动清理（这是刻意的，
  「那是用户练了半小时换来的原文，删不删由他自己决定」），随时可以在收件箱里重试
- **想在不碰真实数据的情况下折腾** → 全程加 `IELTS_SPEAKING_DATA_DIR=/tmp/某个目录` 启动
